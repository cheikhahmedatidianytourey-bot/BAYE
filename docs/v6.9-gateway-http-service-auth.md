# BAYE v6.9 — Gateway HTTP service authentication

## Scope

This release candidate mounts a narrowly scoped machine-to-machine verification endpoint:

- `POST /internal/service-auth/verify`
- Required scope: `gateway:probe`
- HMAC request authentication covers the HTTP method, exact request target, timestamp, nonce, SHA-256 digest of the raw request body, service ID, and key ID.
- PostgreSQL-backed nonce consumption is required when configured, so replay protection survives process restarts and multiple Gateway instances.
- The endpoint is diagnostic and non-mutating. It does not record lifecycle evidence, trigger a mission, or perform an external action.

## Configuration

The endpoint returns HTTP 503 until both environment variables are securely configured:

1. `BAYE_SERVICE_AUTH_DATABASE_URL`: connection string for a dedicated BAYE PostgreSQL database where migration `0063_lifecycle_nonce_store.sql` has been applied.
2. `BAYE_SERVICE_AUTH_REGISTRY`: JSON object keyed by service ID. Each service contains a `scopes` array and a `keys` object keyed by key ID. Every key secret must contain at least 32 bytes.

Example shape only — never use these example values as real credentials:

```json
{
  "research-worker": {
    "scopes": ["gateway:probe"],
    "keys": {
      "key-2026-01": "REPLACE_WITH_A_RANDOM_SECRET_OF_AT_LEAST_32_BYTES"
    }
  }
}
```

Provision the non-login/login role `baye_service_authenticator` and apply migration `0069_service_authenticator_nonce_privileges.sql` after migration `0063_lifecycle_nonce_store.sql`. The migration grants this role only schema USAGE and table INSERT; it does not create the role, credentials, or membership. Use this role for `BAYE_SERVICE_AUTH_DATABASE_URL`. Provision credentials, network access, TLS, secret rotation, and migrations outside the application. Do not reuse another project's database.

## Signing requests

The producer must sign the exact request target including its query string, the decimal Unix timestamp in milliseconds, a fresh URL-safe nonce of 16–128 characters, the SHA-256 hex digest of the exact raw body bytes, service ID, and key ID. Join these seven fields with newline characters in this order:

```text
METHOD
REQUEST_TARGET
TIMESTAMP
NONCE
BODY_SHA256_HEX
SERVICE_ID
KEY_ID
```

Compute HMAC-SHA256 using the configured service key and send the lowercase 64-character hex signature in `x-baye-signature`. Also send `x-baye-service-id`, `x-baye-key-id`, `x-baye-timestamp`, and `x-baye-nonce`.

## Operational boundary

The Gateway does not log registry secrets. Missing, malformed, stale, unauthorized, replayed, or unverifiable requests fail closed. The endpoint's success response is proof only that the configured service key signed this request and that its nonce was accepted; it is not proof that the producer's claims are true. This milestone does not wire the lifecycle evidence writer or any privileged business action.
