# BAYE v7.0 — Mission Intelligence (plan-only)

## Objective

Introduce a provider-neutral planning layer that turns one natural-language mission into a bounded, dependency-aware specialist task graph.

## Endpoint

`POST /api/orchestration/plan`

Request:

```json
{
  "mission": "Design a secure school management application."
}
```

The route uses the configured primary AI provider and is rate-limited to five requests per minute per client. It accepts missions of 1–4,000 characters.

## Planning contract

- The planner may return 1–5 tasks.
- Allowed specialist roles: `coordinator`, `research`, `engineering`, `data`, `creative`, `quality`, `security`.
- Every task has a bounded ID and objective, an explicit dependency list, and an optional positive budget.
- The result is passed through the existing orchestration graph validator with hard limits: 5 tasks, 4 dependencies per task, total budget 10, depth 5.
- Unknown JSON fields, invalid roles, malformed JSON, cycles, missing dependencies, and oversized plans are rejected.

## Approval and execution boundary

This endpoint only generates and validates a plan. The response explicitly reports:

- `status: plan_ready_for_review`
- `approval.required: true`
- `approval.approved: false`
- `approval.executionStarted: false`
- `safety.toolsInvoked: 0`
- `safety.externalActions: false`

It does not call specialist workers, invoke tools, write mission memory, create checkpoints, or perform external actions. Execution remains a separate request to the existing orchestration endpoint; this release does not connect the generated plan automatically to execution.

Structural graph validation does not prove that a plan is semantically complete, factually correct, or optimal. Human review remains required before a caller chooses to execute it.

## Validation

The unit tests use a deterministic mock planner and cover valid plan generation, strict JSON parsing, unknown fields, invalid roles, cyclic dependencies, task limits, and mission input bounds. CI is required to validate the integrated branch.
